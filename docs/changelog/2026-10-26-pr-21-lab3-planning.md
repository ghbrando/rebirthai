# Implementation plan, Issue backlog, and persistent project context

## Summary
Turned the SDD and the already-built MVP into an implementation plan with honest status, a backlog of
20 GitHub Issues on Project 2, and three durable context files agents read on every task.

## Context
CSCI 5520 HW/Lab 3. The MVP had been built before any plan existed, so the plan records real status
instead of pretending to start from scratch (owner's choice).

## What changed
- `docs/IMPLEMENTATION_PLAN.md`: phases 0–7; 0–5 done with commit evidence, 6 = verification and
  gaps, 7 = release readiness; sequence; Issue inventory linked to GitHub; open decisions D-01–D-05;
  risks incl. RISK-09; agent guardrails.
- `docs/issues.json`: the source for Issues #1–#20, generated by the reusable `issues.py`.
- `docs/ARCHITECTURE.md`: components, flows, decisions, 12 rules to preserve, allowed relationships.
- `docs/POLICY.md`: roles, user-facing terminology, truthfulness, safety, privacy, consent, abuse.
- `docs/ROADMAP.md`: direction only; the Project is authoritative.

## Decisions and alternatives
- **Real status over a from-scratch plan**: Issues for built work are closed with evidence so every
  SDD ID stays traceable.
- **AI-created Issues enter at Backlog + Human Review = Pending**; only the owner sets Reviewed and Ready.
- **Lab 2 governance copied from canopy-business** (dev/staging, both rulesets) because this repo had none.

## Assumptions and open questions
D-01–D-05 in the plan. Assumptions A-01–A-05 await owner confirmation.

## Interfaces, data and configuration
GitHub: Project 2 fields Status, Human Review, Phase, Priority, Area, Sequence; labels `ai-generated`,
`type:*`, `blocked`, `human-action`.

## Verification
Script check that every US-01–US-15 and RC-01–RC-14 maps to at least one Issue; board fields
confirmed after creation.

## Known limitations and follow-ups
Owner review of Issues; D-04 domain decision.

## Risks and rollback
Docs only.

## Notes for future agents
- Regenerate or extend Issues by editing `docs/issues.json` and re-running `issues.py` (it skips
  existing keys).
- When status changes, update the plan's §5.1 table and `docs/ROADMAP.md` in the same PR.
