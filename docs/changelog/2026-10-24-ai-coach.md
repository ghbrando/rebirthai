# AI coach: guided interview, resume later, drafts and suggestions from the author's own words

## Summary
A streaming chat coach that asks one question at a time through life before, the turning point and
life after; remembers the conversation across visits; turns the author's answers into a draft; and
offers targeted edit suggestions that never change the draft unless the author accepts them.

## Context
SDD US-03 to US-06, RC-04 (truthfulness), RC-05 (crisis care), RC-08 (speed and cost), DD-04, DD-07.

## What changed
- `app/api/coach/route.ts`: `GET` returns history (resume, US-04). `POST` streams the reply as SSE
  events `{type:"text"}` … `{type:"done", section, covered, message}` or `{type:"error"}`. Empty
  history + no message produces the welcome and first question. Enforces 60 messages/hour.
- `lib/ai/prompts.ts`: the cacheable coach system prompt (one question per turn, arc order,
  truthfulness, skip-any-question, crisis rules with 988) and the draft prompt.
- `lib/ai/coach-data.ts`: finds or lazily creates the caller's testimony through RLS; computes which
  arc sections are covered; `RATE_LIMIT_PER_HOUR = 60`.
- `app/api/coach/draft/route.ts`: draft from the transcript using structured output
  (`zodOutputFormat(DraftOutputSchema)`, adaptive thinking, medium effort); writes `draft_content`.
- `app/api/coach/suggest/route.ts`: returns proposed edits only; keeps a suggestion only if its
  `original` text is an exact excerpt of the targeted block.
- `lib/ai/content.ts`: flat block schema (`h2`/`h3`/`p`) the model fills, converted to the shared
  content shape.
- `components/coach/CoachChat.tsx`: chat UI, streaming, crisis resource display.
- `scripts/coach-eval.ts`: runs scripted fake sessions for the fabrication review.

## Decisions and alternatives
- **Section tags in the model's reply** (`[[section: before|turning_point|after|other]]` at the end)
  track progress without a second model call. The route holds back a trailing tag, and any partial
  `[`, so users never see it.
- **System prompt is fully static** so prompt caching works. Per-request values go in messages,
  never in the system prompt.
- **Structured output for drafts** instead of free text: predictable blocks and validation against
  the shared types.
- **Exact-excerpt rule for suggestions** so accept/reject can locate the text reliably and the
  model cannot "suggest" new material into places it did not quote.
- **Draft uses only the author's turns** (the coach's own words count only if the author affirmed
  them), which is how RC-04 is enforced in practice.

## Assumptions and open questions
- Faith framing (OQ-03) assumed Christian, only if the author wants it.

## Interfaces, data and configuration
`ANTHROPIC_API_KEY` (server only); model `claude-opus-5-5` (`lib/ai/client.ts`). Reads and writes
`coach_messages`; writes `testimonies.draft_content`. The coach, draft and suggest routes return 503 if the key is missing.

## Verification
Built and type-checked. The SDD's gate, five sessions with zero invented details, has **not** run (#10).
The 2-second first-token target has not been measured (#16).

## Known limitations and follow-ups
Fabrication review (#10). Rate limit counts messages in the database (no separate store).

## Risks and rollback
Prompt edits can reintroduce fabrication or break section tagging; rerun `scripts/coach-eval.ts` after
any prompt change.

## Notes for future agents
- Do not interpolate anything into the system prompt (breaks caching and cost control, RC-08).
- If you change the section tag format, update the regex in `lib/ai/prompts.ts` and the hold-back
  logic in `app/api/coach/route.ts` together.
- The model API needs the first turn to be a user turn; the route builds messages accordingly.
- Never let suggest write to the draft; the editor applies accepted suggestions.
