# Installable app: manifest and icons

## Summary
RebirthAI can now be installed to a phone's home screen with its own name, maroon theme and "R" icon, and opens straight into the dashboard.

## Context
Issue #12 (RC-14, DD-01): no web app manifest existed.

## What changed
- `app/manifest.ts`: name/short name "RebirthAI", `start_url` /dashboard, `display: standalone`, theme #7a2e3a, background #ffffff, icons 192, 512, maskable 512.
- `public/icons/*.png` and `app/apple-icon.png` (180): generated by `scripts/generate-icons.mjs`.
- `app/layout.tsx`: `viewport.themeColor`.

## Decisions and alternatives
- PNG generator script with Node built-ins (zlib) over `app/icon.tsx` with `next/og`: static files are cached and need no runtime; no new dependency.
- No service worker/offline: out of scope in the Issue; modern Chrome installs without one.
- Background color white (the app's page color) rather than maroon.

## Assumptions and open questions
Chrome install prompt and iOS appearance not verified on a device (no browser allowed in this pass).

## Interfaces, data and configuration
New public routes `/manifest.webmanifest`, `/icons/*`. No dependencies, env vars or schema.

## Verification
`npm run lint`, `npm run typecheck`, `npm test` pass. Icon rendered and visually checked. DevTools manifest check and phone screenshot still to do (can be done in I-14).

## Known limitations and follow-ups
No offline mode, push or native app (out of scope).

## Risks and rollback
Low. Remove `app/manifest.ts` and the icons to revert. `/dashboard` as start URL sends signed-out users to sign-in.

## Notes for future agents
To change the icon design, edit `scripts/generate-icons.mjs` and re-run `node scripts/generate-icons.mjs`; commit the outputs.
