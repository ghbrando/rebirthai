## Findings

1. **Settings and first-time profile setup show a localhost link** ([screenshot](finding-settings-link-localhost.png)). Under the Handle field the text reads "Your link: http://localhost:3000/@maria_g" even though the site address is set. The server renders the correct address, then the browser replaces it with localhost; this logs a React hydration error (#418) and makes `npm run smoke` fail on /settings. Cause: `components/profile/profile-form.tsx` (a client component) calls `permanentUrl()`, which calls `getSiteUrl(process.env)`; in the browser that `process.env` object is not filled in, so it falls back to `http://localhost:3000`. Local dev hides it because localhost is the real address there. On a deployed site every author would see a wrong link on Settings and on profile setup. Display only: saved data, contact cards, QR codes, dashboard and share links are correct. Severity: medium. Nobody is blocked.
2. **Contact card: after saving, "Include my email" shows as off while the email is still included** ([screenshot](finding-contact-checkbox-after-save.png)). Steps: /contact, turn on Include my email, type an email, Save. "Saved." appears and the database keeps the email, but the checkbox now shows unchecked (the email field stays visible). Pressing Save again without touching anything removes the email (contact_email becomes null). Likely cause: React 19 resets the form after the server action, and the controlled checkbox goes back to its first-render value. The phone checkbox uses the same pattern. Severity: medium (the screen shows the wrong sharing choice, and a second Save silently removes a contact detail the author chose to share). Nobody is blocked; reloading the page shows the correct state.
